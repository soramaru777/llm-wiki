# LLM Wiki スキーマ

このファイルが**唯一の正のスキーマ定義**。各プロジェクトの `CLAUDE.md` はこのファイルを参照するだけにし、内容を複製しないこと。

Karpathy の LLM Wiki パターン（2026-04）に基づく。RAG のように毎回生資料を検索するのではなく、**取り込み時に知識をコンパイルし、質問時は完成済み Wiki を読む**。

---

## 1. 構成

グローバル vault（`~/wiki`）とプロジェクト内 wiki の2層。

```
~/wiki/                              # グローバル vault（個人・横断）
├── SCHEMA.md                        # このファイル
├── index.md                         # 全ページの1行カタログ
├── log.md                           # 追記のみの操作ログ
├── knowledge/                       # 横断知識（2プロジェクト以上で使う知見）
├── projects/<name>.md               # プロジェクトのハブページ
└── mounts/<name> -> <repo>/docs/wiki  # 各リポジトリの wiki への symlink

<repo>/docs/
├── raw/                             # 不変のソース（LLM は書き換えない）
└── wiki/                            # LLM が保守するページ + index.md + log.md
```

### どちらに置くか

**判断基準: そのリポジトリを他人に渡したとき、一緒に行くべき知識か？**

- Yes → `<repo>/docs/wiki/`（アーキテクチャ、設計判断、既知の課題、運用手順）
- No → `~/wiki/knowledge/`（ライブラリ・API・言語の一般知見、自分の作業スタイル）

### 昇格ルール

**同じ知見が2プロジェクト以上で出てきたら `~/wiki/knowledge/` へ移し**、各プロジェクトからはリンクで参照する。重複を放置しない。

## 2. ページ

### frontmatter（全ページ必須）

```yaml
---
title: 人間が読むタイトル
type: concept | entity | decision | issue | source-summary | comparison | howto | hub
project: <プロジェクト名> | global
scope: shared | private        # private = 個人的な好み・作業ログ。共有リポジトリには置かない
sources:                        # 出典。空のページは lint で警告
  - docs/raw/xxx.md
  - https://example.com/...
related: [[other-page]]
confidence: high | medium | low  # low = 未検証・推測を含む
updated: YYYY-MM-DD
---
```

### 命名規則

- ケバブケース、`<project>-<topic>.md`（例: `<project>-architecture.md`）
- **プロジェクト prefix を必ず付ける**。`architecture.md` のような汎用名は mounts 集約時に衝突する
- `knowledge/` 配下は prefix 不要（例: `deepgram-streaming-ja.md`）

### 本文

- 冒頭1〜2行で「このページは何か」を書く。ここだけ読んで判断できること
- 関連概念は `[[wikilink]]` で結ぶ。存在しないリンクを張ってよい（次に書くべきページの印になる）
- **推測と事実を混ぜない**。未検証は `confidence: low` にし、本文にも「未検証」と明記する

## 3. 操作

### ingest（取り込み）

1. ソースを `docs/raw/`（またはグローバルなら `~/wiki/raw/`）に置く。**以後このファイルは変更しない**
2. 全文を読み、要点を抽出する
3. 該当する既存ページを**更新**する。新規追加だけで済ませない（原案の最大の弱点）
   - 事実が変わった場合は本文を書き換え、旧記述は `> 〜まで: ...（YYYY-MM-DD 更新）` の形で残す
4. 新しい概念があればページを新規作成する
5. `index.md` に1行追加、`log.md` に追記
6. 1ソースで**10〜15ページに波及するのが正常**。1ページしか触っていないなら取り込みが浅い

### query（照会）

1. まず `index.md` を読み、次に関連ページを読む。生ソースは最後の手段
2. 回答には**必ずページ名を引用**する（`<project>-open-issues.md より` のように）
3. Wiki に答えがなければ「Wiki に無い」と明言してから調べる。**推測で埋めない**
4. 調べた結果に再利用価値があれば、新しいページとして書き戻す

### lint（点検）

週次を目安に実行。

- **矛盾**: 同じ事実について異なる記述をしているページの組
- **陳腐化**: `updated` が古く、ソースが更新されているページ
- **孤立**: どこからもリンクされていないページ
- **リンク切れ**: 存在しないページへの `[[link]]`（=書くべきページ。リストとして提示する）
- **出典なし**: `sources` が空のページ
- **昇格候補**: 複数プロジェクトで重複している知見
- **index 不整合**: `index.md` に載っていないページ、実体のない項目

**lint は検出を報告するだけで、自動修正しない。** 修正は人間の承認を得てから。

## 4. 運用ルール

- **`raw/` は不変**。人間か ingest 処理だけが追加でき、既存ファイルは書き換えない
- **すべて可逆に**。破壊的な整理をする前に git commit で退避する
- **機密を書かない**。API キー、トークン、パスワードは Wiki に一切書かない。「`.env` に設定済み」とだけ書く
- **ハルシネーション対策**。出典のない断定を書かない。分からないことは書かないか `confidence: low` にする
- **チーム共有時**: LLM の書き込みを直接 main に入れず、必ず PR レビューを通す。ingest 実行者は1人（または CI）に固定し、他メンバーは `raw/` に積むだけにする
