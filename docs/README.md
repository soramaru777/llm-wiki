# LLM Wiki ドキュメント

**AI に知識ベースの司書をやらせる仕組み**、LLM Wiki の入門から運用までのドキュメントです。

「聞いたことはあるが何なのか分からない」「導入したが何をすればいいのか分からない」という状態から、実際に運用を回せるところまでを想定しています。

---

## これは何を解決するのか

Claude Code のようなコーディングエージェントを使っていると、こうなりがちです。

- セッションが変わるたびに**プロジェクトの経緯を説明し直している**
- 「前に決めたはずのこと」を毎回コードから読み直させていて、**遅いし高い**
- 調べた結果がチャットログの底に沈んで、**二度と見つからない**

LLM Wiki は、**調べた結果・決めたことを AI が Markdown の Wiki として書き溜め、次からはそれを読む**ようにする仕組みです。2026年4月に Andrej Karpathy が提唱し、広まりました。

## 3行で言うと

1. 資料を **ingest（取り込み）** すると、AI が Markdown の Wiki を書いて相互リンクを張る
2. 質問（**query**）には、その Wiki を読んで**ページ名を引用しながら**答える
3. 週1回 **lint（点検）** して矛盾や古い記述を潰す ← **これをやらないと成立しない**

## 向いているもの・向いていないもの

**向いている**

- 数週間以上かけて育てるプロジェクト
- セッションを跨いで続く仕事
- 自分が全体像を把握しておきたい対象

**向いていない**

- 一度読んで終わりの資料 → そのまま AI に読ませたほうが速くて安い
- 数百万件規模の文書検索 → RAG のほうが適している
- 休眠中のプロジェクト → 名前を一覧に書くだけで十分
