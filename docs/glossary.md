# 用語集

このドキュメントで使う言葉の一覧です。

---

## 操作

### ingest（インジェスト / 取り込み）
資料を Wiki に取り込む操作。AI が資料を読み、**関連する既存ページをまとめて書き換え**、必要なら新しいページを作ります。1つの資料で複数ページに波及するのが正常です。

### query（クエリ / 照会）
Wiki を読んで質問に答える操作。生の資料ではなく、整理済みのページを読みます。回答には必ず**根拠のページ名**が付きます。

### lint（リント / 点検）
Wiki 全体を点検する操作。矛盾・古い記述・孤立ページ・リンク切れなどを**検出して報告するだけ**で、自動修正はしません。週1回が目安です。

> プログラミングの「lint（静的解析）」から借りた言い方です。

## 場所

### vault（ヴォールト / 保管庫）
Markdown ファイルをまとめて置くフォルダのこと。ここでは `~/wiki` を指します。Obsidian 由来の用語です。

### raw/（ロー）
**生の資料**を置くフォルダ。仕様書、議事録、記事のクリップなど。**一度置いたファイルは書き換えません。**AI は読むだけです。

### wiki/
**AI が書いて維持するページ**を置くフォルダ。raw/ の内容を要約・構造化したものが入ります。

### knowledge/
複数のプロジェクトで使える**横断知識**を置くフォルダ。`~/wiki/knowledge/` にあります。

### projects/
各プロジェクトの概要をまとめた**ハブページ**を置くフォルダ。`~/wiki/projects/` にあります。

### mounts/
各プロジェクトの `docs/wiki/` への**ショートカット（symlink）**を集めたフォルダ。これにより `~/wiki` を開くだけで全プロジェクトを横断できます。

## ファイル

### SCHEMA.md
**ページの規約**を定義するファイル。frontmatter の項目、命名規則、置き場所の基準、3つの操作の手順を書きます。**唯一の正**とし、各プロジェクトには複製しません。

### OPERATIONS.md
**運用手順**を定義するファイル。「いつ何を実行するか」だけを扱います。SCHEMA.md と役割を混ぜません。

### index.md
**全ページの1行カタログ**。AI が最初に読む入口です。ページを追加したら必ず1行足します。これが無いと全体を見失います。

### log.md
**操作ログ**。追記のみで、新しいものを下に足します。「いつ何を取り込んで何が変わったか」を残します。

### CLAUDE.md
Claude Code がプロジェクトを開くたびに**自動で読むファイル**。ここに「作業前に `docs/wiki/index.md` を読むこと」と書いておくと、毎回指示しなくても Wiki を見に行きます。

## ページの要素

### frontmatter（フロントマター）
Markdown ファイル冒頭の `---` で囲まれた部分。`title` `type` `sources` `confidence` などのメタ情報を書きます。

```yaml
---
title: TaskFlow アーキテクチャ
type: concept
confidence: high
---
```

### wikilink（ウィキリンク）
`[[ページ名]]` の形式で他のページへ張るリンク。**存在しないページへ張ってもよく**、その場合は「次に書くべきページ」の印になります。

### confidence（確度）
その記述をどれだけ信用してよいかの格付け。

| 値 | 意味 |
|---|---|
| `high` | 実機・実測で確認した |
| `medium` | 仕様上そうなるはず |
| `low` | **未検証**。推測を含む |

**ハルシネーション対策の要**です。AI は放っておくと未検証も断定調で書くため、人間が格付けし直します。

### sources（出典）
その記述の元になった資料。空だと lint が警告します。**出典のない断定を書かせない**ためのものです。

### scope（スコープ）
`shared`（共有してよい）か `private`（個人的な好み・作業ログ）かの区別。チームで使うときに効きます。

## 運用の概念

### 昇格
プロジェクト固有として書かれた知識を、`~/wiki/knowledge/` の**横断知識に格上げする**こと。同じ知見が2プロジェクト以上で出てきたら昇格させます。

### 差分レビュー
取り込み直後に `git diff docs/wiki` で変更内容を確認する作業。**訂正の妥当性・確度の格付け・機密の混入**の3点だけを見ます。この運用でいちばん重要な工程です。

### ハブページ
プロジェクトの概要・現在地・次にやることをまとめた入口ページ。`~/wiki/projects/<name>.md` に置きます。

## 関連する用語

### RAG（検索拡張生成）
Retrieval-Augmented Generation。質問のたびに資料をベクトル検索して関連部分を引っぱり、それを踏まえて回答する仕組み。LLM Wiki と対比されます。

- RAG = 倉庫から都度取り出す
- LLM Wiki = 司書が整理し続ける図書館を読む

### 埋め込み（embedding）
テキストを数値ベクトルに変換したもの。RAG の検索に使います。**LLM Wiki では不要**です。

### Agent Skills
Claude Code などのエージェントに操作手順を教える仕組み。`~/.claude/skills/<name>/SKILL.md` に置くと、全プロジェクトから `/<name>` で呼べます。

### symlink（シンボリックリンク）
別の場所にあるファイルやフォルダへのショートカット。`mounts/` で使い、実体をプロジェクト側に残したまま vault から見えるようにします。

```sh
ln -sfn <実体のパス> <ショートカットのパス>
```
