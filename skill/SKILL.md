# LLM Wiki

**最初に必ず `~/wiki/SCHEMA.md` を読むこと。** ページ型・frontmatter・命名規則・置き場所の判断基準はすべてそこに定義されている。このファイルは操作手順のみを扱う。

## 置き場所の判定

- カレントのリポジトリに `docs/wiki/` があれば、それがプロジェクト wiki
- なければグローバル vault（`~/wiki`）を対象にする
- **リポジトリを他人に渡したとき一緒に行くべき知識か？** Yes → プロジェクト wiki、No → `~/wiki/knowledge/`

## ingest — 取り込み

引数でソースを受け取る（ファイルパス、URL、または「この会話の内容」）。

1. ソースを全文読む。URL なら WebFetch する
2. ファイルなら `docs/raw/` に配置する（既に raw にあるならそのまま）。**一度置いたファイルは書き換えない**
3. 対象 wiki の `index.md` を読み、既存ページの全体像を把握する
4. **既存ページを更新する。** 新規作成だけで終わらせない
   - 事実が変わったら本文を書き換え、旧記述は `> YYYY-MM-DD 更新:` の形で残す
   - 撤回された前提は `> 訂正:` として明示する
5. 新しい概念があればページを新規作成する（frontmatter 必須）
6. `[[wikilink]]` で関連ページを相互に結ぶ。**片方向で終わらせない**
7. `index.md` に行を追加し、`log.md` に `YYYY-MM-DD ingest — 要約` を追記する
8. 他プロジェクトでも通用する知見は `~/wiki/knowledge/` に切り出し、プロジェクト側からリンクする

**1ソースで複数ページに波及するのが正常。** 1ページしか触っていないなら取り込みが浅い。

**書いてよいのは出典に基づく内容だけ。** 推測で埋めない。未検証は `confidence: low` にし、本文にも明記する。

## query — 照会

1. `~/wiki/index.md` → 対象プロジェクトの `docs/wiki/index.md` の順に読む
2. 関連ページを読んで回答を組み立てる。**生ソース（`raw/`）は最後の手段**
3. **回答には必ずページ名を引用する**（`taskflow-open-issues.md より` の形式）
4. Wiki に答えがなければ「Wiki に無い」と明言してから調べる
5. 調べた結果に再利用価値があれば、新しいページとして書き戻すか提案する

## lint — 点検

対象 wiki の全ページを読み、以下を**検出して報告する**。

- **矛盾** — 同じ事実について異なる記述をしているページの組
- **陳腐化** — `updated` が古く、ソース側が更新されているページ
- **孤立** — どこからもリンクされていないページ
- **リンク切れ** — 存在しないページへの `[[link]]`（= 次に書くべきページ。リストで提示する）
- **出典なし** — `sources` が空、または frontmatter 自体が欠けているページ
- **昇格候補** — 複数プロジェクトで重複している知見
- **index 不整合** — `index.md` に載っていないページ、実体のない項目

**自動修正しない。** 検出結果を提示し、どれを直すか確認してから修正する。修正したら `log.md` に追記する。

## 共通ルール

- API キー・トークン・パスワードを Wiki に書かない。「`.env` に設定済み」とだけ書く
- git 未追跡のファイル（`docs/local/` など）の内容を Wiki に複製しない。参照先として名前を挙げるに留める
- 破壊的な整理をする前に git commit で退避する
